# .handoff —— 交接目录约定

> 触发方式：用户说「交接」。执行规程在 `~/AGENTS.md`（很短），细节全在这里。

## 0. 三个词，别混

| 词 | 含义 | 代价 |
|---|---|---|
| **交接 succession** | 换一个**新的顶层会话**继续，旧会话冻结。**本目录服务的就是它** | 写 INDEX + 继任者冷启动，≈¥0.15–0.25 |
| **委派 delegation** | 主会话不变，派子代理干活 | 多起一整条 agent 循环（39 步 × high 档 = ¥0.4–1.6/任务） |
| **压缩 compaction** | 原地重写历史（同一会话） | **不是交接**；实测会打掉前缀缓存（Copilot 生产数据：命中率中位 **−66%**，34% 的事件抹掉 ≥90%） |

## 1. 目录布局（只此一处，禁止散落）

```
.handoff/
├── README.md              本文件
├── CONTEXT.md             术语表（只有词汇，不含实现）
├── adr/                   决策记录
├── INDEX.template.md      交接文档模板
├── <MMDD-HHMM>-<slug>/    一次交接 = 一个目录
│   └── INDEX.md           唯一必读，≤60 行
│       （files.md / errors.md / research/*.md 等分册按需，由继任者自己写）
├── reports/               子代理报告（用完删正文，留摘要）
└── review/                每周复盘输出
```

任何交接相关文件都必须在 `.handoff/` 或其子目录内。代码仓库请把 `.handoff/` 加进 `.gitignore`。

## 2. 交接文档：便条级，不是报告

六项字段，缺一不可：

1. **目标**：1–2 句，可验证
2. **已完成**：只写结果 + 产出文件的**绝对路径**
3. **未决**：现在到底卡在哪
4. **下一步**：1–3 条，可执行
5. **硬约束**：不能碰的东西 / 已验证的事实（每条标状态，见 §3）
6. **验证方式**：怎么判断做对了

硬上限：**≤70 行、≤1.5k tokens**（2026-09-19 从 60 行/1.2k 上调，理由见下）。禁止贴代码、日志、网页原文——只给路径或 URL + 一句结论。

**要超了先砍哪里**：先砍"历史过程"（修过哪些 bug、怎么试的），**绝不砍**硬约束、验证命令、证据路径、状态标记。

> **为什么上调**：实测第一份交接件 1101 tokens（占满 1.2k 的 92%）后，仍被继任者查出 3 处"照抄即错"的硬错误（文件名不存在、判据歧义、数字张冠李戴），纠正它们必然增加篇幅（现为 1462 tokens）。
> **代价核算**：多出的 ~360 tokens，按缓存命中价 ¥0.02–0.04/M、继任会话 50 轮计 ≈ **¥0.0003**；而一个错文件名会让继任者多跑一次失败命令 + 一次重试循环 ≈ **¥0.02–0.05**。**精度比字数便宜两个数量级。**
> 真正要抠的不是字数，而是"把内容抄进来"：代码/日志/原文一律变成指针——那才是每一轮都在付费的部分。


## 3. 结论状态：三种，**全文都要标**

**作用范围：§2 已完成、§3 未决、§5 硬约束、§6 验证方式里的每条判断句都要标**——不只是硬约束节。

- `[有效]` —— 已实测/已验证，**必须附"证据"路径（输出文件/测试结果/日志），不是"相关文件"路径（脚本/源码）**
- `[存疑]` —— 推断但未验证：继任者可以照做，但**不得当作前提继续推导**
- `[已否证]` —— 曾被认为成立、后来被证伪：**必须留档**，写清"错在哪、为什么错"，防止下一个人重犯（例：`√(25²+25²)=35.36` 这个猜测被差向量否证，真因是判向符号错 50 mm）

> 2026-09-19 实测教训（两条，都出自真实交接件）：
> ① 一条 `[有效]` 把"effort medium 已生效"写在 §2 且没标状态，而该值在本环境**非法**（只接受 `off`/`high`/`max`）——继任者会照单全收。
> ② 另一条 `[有效]` 写"新工具**现场** **7/7** 通过"，附的路径却是**脚本**：实际 7/7 属于**另一个工具**（点动导航自检），本工具的真实证据是**离线 6/6**。→ 所以"证据路径"必须指向**产出**，不能指向**代码**。


- 交接者有义务标出"我推断但没验证"的条目。


> 依据：GPT-4 单独看能识别错误论断准确率 **87.03%**，但放进上下文后正确率仅 **16.6%**（Snowball, arXiv 2305.13534）；多轮对话 15 个模型平均 **−39%**、不可靠性 **+112%**（Get Lost, arXiv 2505.06120）。

## 4. 继任者的检索纪律（本地优先）

顺序：`grep`/`read` 具体文件 → 项目文档/`AGENTS.md` → `.handoff/` 里的旧 INDEX 与报告 → **兜底才联网**。

预算：一轮内 ≤15 次工具调用、网页 ≤2 次；超预算就停下来问用户。

**这条预算必须写在 INDEX 头部**（模板已带），因为继任者**只读 INDEX，不会去读本文件**——
2026-09-19 实测：继任会话做了 **23 次工具调用**，超出预算 53%，就是因为它看不到这条规则。
（这 23 次里含 1 次核心核验 + 8 条附带发现，价值很高；所以预算的作用是"提醒收手"，不是硬闸。）


禁止：无差别重读旧会话全文（那等于把省下来的上下文又买回来）。

## 5. 子代理（委派）规则

- **禁止再派子代理**：preset `standard-leash` 已用 `maxDepth: 1` + `toolFilter.deny` 封死（结构强制，非靠自觉）。
- 详细结果写 `.handoff/reports/<YYYYMMDD>-<slug>.md`，**第一段是 ≤10 行结论摘要**（重要在前）。
- 回给上级**只允许**：≤10 行摘要 + 文件绝对路径 + 没能确定的事。禁止把长文/原始材料贴回上级上下文。
- 上级取用后：要点抄进 INDEX，然后**删掉报告正文**（摘要段可留档）。

## 6. 档位（reasoning effort）

DeepSeek 这条线只有 `off` / `high` / `max`（`low`/`medium` 会被适配器直接拒绝；`medium` 是 `high` 的别名）。

- **会话起始就定档**：执行型会话 `off`，决策/反思型会话 `high`。
- **换档只在上下文 <30k 时做一次**：实测 30k 前缀首次启用新档位 = 一次全冷（约 ¥0.06）；在 250k 上下文里首次启用 = **¥0.5 且要多等 ~20 秒**。
- **绝不按轮次切档**（每个 effort 值是一条独立缓存谱系，来回切看似免费，但每次新档位首次出现都要全价重读）。
- `max` 不常设；用 `max` 时必须**显式压 `max_tokens`**（该档默认会抬到 128K）。
- 子代理一律走 `deepseek-cheap`（`thinking: disabled`），机械活用 `off`、推理活别用它。

### 谁能换档（重要）

**模型无权改自己的档位**：DSH 没有面向模型的 effort 工具，`AgentOptions` 只有 `provider/model/maxTokens`，`reasoningEffort` 是唯一没有 per-agent 配置路径的旋钮。所以"自己给自己换挡"做不到；能做的只有下面三种形态：

| 形态 | 怎么做 | 适合 | 代价 |
|---|---|---|---|
| **A. 主会话守 `high`，机械活交给 `off` 子代理** | 直接委派（`standard-leash` 里 `subagent` 已指向 `deepseek-cheap`＝off） | 抓取/整理/跑脚本/批量改文件 | 子代理只回 ≤10 行摘要，细节在报告文件里 |
| **B. 把"深思考"交给 `max` 子代理** | 需要**再加一条 `reasoning: "max"` 路由** + 一个**独立 `toolName`** 的委派行（同一行只能钉一条路由） | **自包含**的难题：证一个公式、判一个几何、推一个反例 | 子代理没有主会话的全局背景 → 判断类任务会失真；且会多一套工具占 context |
| **C. 主会话自己换档（由你切）** | GUI 的模型/档位选择，或新开会话时定档 | 需要**全局视野**的深思考 | 换档＝该档位在本会话首次出现＝一次全冷（<30k 时约 ¥0.06；250k 时 ¥0.5 + 多等 ~20 秒） |

默认策略：**A 常开；B 只在确有"可自包含的难题"时加；C 由你在会话早期一次性决定**（<30k 时换档几乎免费）。


## 7. 旧会话的命运与回退

交接后旧会话**冻结**（只读参考，不再续跑）。走偏了**不要复活旧会话**——再交接一次，新 INDEX 指向前一个 INDEX。

## 8. 每周复盘

每周跑一次 `python3 ~/.dsh-analysis/weekly_review.py [--days N]`（默认 7 天），输出到 `review/<日期>.md`。
脚本实际测六节（文档只说这六节，不承诺没测的东西）：

1. **花费**：总额 + token 类别占比 + 按天 + 按 provider，对照基线 `2026-09-09~09-19 共 ¥68 / 11 天 = ¥6.2/天`
2. **冷读**：分两类——*会话中途冷读*（异常，`cr=0` 且未命中 ≥20k）与*会话首个请求*（预期内冷启动）
3. **子代理**：会话数 / 总花费 / 单任务均花费 / `delegationDepth` 分布（**depth≥2 应为 0**，出现即 `standard-leash` 未生效）
4. **交接**：交接目录数 + **每次交接后 24h 的主会话花费**
5. **步骤重复**：同一会话内同一条 `bash` 命令出现 ≥3 次（MAST 测得的头号失败模式）
6. **建议**：按阈值给 1–3 条（输出占比 >45%、子代理占比 >35%、冷读>0、depth≥2、步骤重复）

> 口径提醒：脚本按 DeepSeek 官方价估算；走包月套餐（`ark-*`）的请求边际成本记为 0；
> **非 DeepSeek 路由（`zai-*` 等）是同价估算，不是真实账单**。跨路由比较只看趋势。

**交接成本实测基线**（2026-09-19，`session-78758a4e` 首轮自检）：
**¥0.068 / 17 次请求 / 23 次工具调用 / 终态上下文 30k** —— 即"继任者从冷启动到可开工"约 **¥0.07**，
低于原先 ¥0.15–0.25 的估算。这也补上了外部检索留下的缺口（"没人测过继任者要花多少才能恢复"）。

**证据库**：`research/` 下按调查分目录（顶层是结论文件，`_raw/` 是原始抓取，可删）。
ADR-0001 引用的全部数字都出自 `research/2026-09-19-handoff-evidence/`。

## 9. 产物该放哪（目录即分类）

| 产物 | 唯一位置 | 说明 |
|---|---|---|
| 交接件 | `~/.handoff/<MMDD-HHMM>-<slug>/INDEX.md` | 一次交接一个目录；分册由继任者按需写 |
| 子代理报告 | `~/.handoff/reports/<YYYYMMDD>-<slug>.md` | 首段 ≤10 行摘要；上级取用后删正文 |
| 周复盘 | `~/.handoff/review/<YYYY-MM-DD>.md` | 脚本自动写 |
| 研究证据 | `~/.handoff/research/<日期>-<调查名>/` | 顶层＝结论文件；`_raw/`＝原始抓取 |
| 决策记录 | `~/.handoff/adr/NNNN-<slug>.md` | 三个条件全满足才写（难反转 + 需要背景 + 真实取舍） |
| 度量/验收脚本 | `~/.dsh-analysis/*.py` | 可重复跑：`weekly_review.py`、`verify_leash.py` |
| 项目产物 | **项目目录内** | 绝不留在 `$HOME` 顶层 |

**硬规则：不在 `$HOME` 顶层新建目录。** 临时文件放 `/tmp` 或 `~/.dsh-analysis/tmp/`。

> 历史遗留（`~/research`、`~/ft_research`、`~/ur_research` 等约 1.4GB，2026-09-19 之前产生）**暂不处理**，
> 等用户决定：可整体移到 `.handoff/research/_legacy/`，或按清单勾选删除。

## 10. 验证一次交接（可选，约 5–6 次工具调用）

交接刚做完、想确认继任者接得住时，在**新会话**里贴这段：

> 读 `<INDEX 绝对路径>`。这一轮只做交接自检：不改文件、不跑长任务、不派子代理。
> ① 用 5 行复述：目标 / 当前卡点 / 下一步第一条 / 最要紧的硬约束 / 标 `[存疑]` 的条目
> ② 挑 1 条 `[有效]` 去读对应文件核验，说明是否属实
> ③ 指出 INDEX 里矛盾、含糊或缺失的地方
> ④ 说明下一步第一条是否需要我（用户）先做动作
> ⑤ 最后一句回答：可以直接开工，还是需要先补信息

（这是"想验证时"用的一轮，**不是强制规程**——按 Q17 的决定，不设强制"只验证不实现"。）
