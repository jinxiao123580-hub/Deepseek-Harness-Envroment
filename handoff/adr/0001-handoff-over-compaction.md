# ADR 0001 —— 用「交接」而不是靠 compaction 来防降智与省成本

- **状态**：已接受（2026-09-19）
- **决策者**：用户 + 代理（依据实测与外部证据）
- **相关**：`.handoff/README.md`、`.handoff/CONTEXT.md`
- **证据库**：`research/2026-09-19-handoff-evidence/`（顶层 `part_*.md` / `vendors_*.md` / `academic.md` 是结论与逐条 URL，
  `_raw/` 是原始抓取，可删）；本 ADR 里每个数字都能在那里找到出处与 [MEASUREMENT]/[ARGUMENT]/[ANECDOTE] 分级。

## 背景

一个长会话跑久了会同时出现两个问题：

1. **钱**：实测 2026-09-09 ~ 09-19 共 3928 次请求花了 ¥68；单会话最高 ¥14.57（385 步、平均上下文 250k）。成本按"上下文 × 请求数"累积：在 250k 上下文时每一步约 ¥0.038。
2. **质**：用户的主观痛点是"**被自己以往的错误结论限制**"。这不是错觉：GPT-4 单独看能识别错误论断 87.03%，放进上下文后正确率只剩 16.6%（Snowball 2305.13534）；15 个模型多轮对话平均 −39%、不可靠性 +112%（Get Lost 2505.06120）；自我纠错普遍把成绩改坏（CommonSenseQA 75.8 → 38.1，Huang 2310.01798）；自我批判 55% vs 外部验证器 88%（Valmeekam 2310.08118）。

环境约束（实测）：上下文一旦被改写或档位一变，前缀缓存即失效（本机实测：同一 30k 前缀，换档后首次请求 `cache_hit=0`、耗时 23.4s vs 命中时 0.6s）；而 DeepSeek 的缓存命中价只有 ¥0.02–0.04/M，是全部成本结构里最便宜的一环（本机 97.7% 的 token 是缓存命中读）。

## 决策

**长任务在上下文变长之前"换人"：写出便条级交接文档 → 开一个新的顶层会话继续 → 旧会话冻结。**

不采用"靠 compaction 原地续命"作为主要手段；也不采用"放任长上下文"。

## 依据

**支持交接的证据**

| 事实 | 数字 | 来源 |
|---|---|---|
| compaction 砸掉前缀缓存（生产规模） | 触发于 7.8% 会话但覆盖 44.2% token；prompt token 中位 −72.8%；**缓存命中率中位 −66.1%**，34.3% 的事件抹掉 ≥90%；延迟占单轮中位 22%、P90 34% | arXiv 2608.00101 |
| compaction 丢事实 | 一次 36.7× 压缩后 **60% 事实不可恢复**；项目约束 91% → 62% → 46%（三次级联） | arXiv 2603.17781 |
| 摘要并不优于"直接丢弃旧观测" | SWE-bench Verified：53.8% vs 54.8%；$0.64 vs $0.61/例 | arXiv 2508.21433 |
| 少给历史反而更好 | SWE-agent：全历史 15.0% vs 只留最近 5 条观测 18.0% | arXiv 2405.15793 |
| 长会话的典型死法 | 步骤重复占多智能体失败 15.7%；≥10 次重复动作的轨迹 >25%；给定 10 连重复后失败概率 89%；53% 的失败轨迹被成本/步数上限终止 | MAST 2503.13657 / SWE-smith 2504.21798 |
| 有产品这样做过 | Amp 于 2025-10-23 上线 Handoff（"no more compaction"），2026-01 支持自然语言触发 | ampcode.com/news/handoff |

**反对交接的证据（必须记录）**

| 事实 | 来源 |
|---|---|
| Amp 在 2026-05 "Amp, Rebuilt" 里**删掉了 Handoff、改回自动 compaction**（"Handoff is gone… compaction made it obsolete"），而它自己的文档至今仍教用户用 Handoff | ampcode.com/news/neo 与 /docs/threads（自相矛盾） |
| Anthropic 报告：Sonnet 4.5 时代"compaction alone wasn't sufficient，context resets became essential"，到 Opus 4.5 又不再需要 | Anthropic engineering 2026-03-24 |
| 没有任何一方测过"交接后要花多少次工具调用才能恢复到可工作状态" | 检索缺口 |

→ 因此结论是**模型/规模相关**的：不是普适真理，必须用自家数据每周复核（见 `README.md` §8）。

## 后果

- **得到**：上下文可控（每轮成本不再随步数线性膨胀）、错误结论不会长期驻留、档位可免费重选（新会话本来就冷启动）。
- **付出**：继任者要重新推导一部分东西；交接文档本身有成本（≈¥0.15–0.25/次）；旧会话冻结意味着"回退"要再交接一次。
- **不打算做**：用 compaction 兜底防降智；用长上下文硬扛；让子代理无上限扇出（2026-09-19 实测一次失控扇出：2 个调查 → 20 个代理 → 单日 ¥8.34，主对话仅 ¥0.59）。

## 何时推翻本决策

每周复盘（`review/`）中若连续两周出现：交接后返工率高、继任者恢复成本超过省下的钱、或模型换代后长上下文不再明显降智 —— 则重开本 ADR。
