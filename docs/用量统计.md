# 用量统计 —— 按机器分栏

> **为什么单独开一份**：README 早先把两个不同口径的用量并在一张表里，留下"¥68 vs ¥189.46 对不上账"的悬案。
> 用量数字**不可跨机引用**（provider 组合、档位、会话习惯都不同）；把这个文件当成"每台机器一段"的登记处。

## 0. 怎么复现（唯一产出方式）

本机没有可用的裸 `python`（Microsoft Store 占位器）、也没有 `zstd` CLI，用 `uv` 兜底：

```powershell
uv run --no-project --python 3.12 --with zstandard python scripts/cost_anatomy.py --days 3650 --top 12
```

- **必须写明 `--days` 与机器** —— 同一脚本不同窗口给出的是不同口径的数。
- 脚本只读 `$DSH_HOME/sessions/` 下的 `.zstd` 会话日志，全部本地解压，**不上网、不读凭据**。
- 下面每段都标明"实测段 + 命令"，与产出文件一一对应。

## 3. 周复盘（六节指标 · 同一台机器、同一批日志）

```powershell
uv run --no-project --python 3.12 --with zstandard python scripts/weekly_review.py --days 40
```

产出：`~/.handoff/review/2026-09-19.md`（本次运行生成；控制台里的中文会显示成乱码，
**那是 PowerShell 代码页 936 的显示问题，落盘的 md 文件本身是正常 UTF-8**）。

| 节 | 值 |
|---|---|
| 花费 | **¥189.46** / 15380 请求 = **¥0.0123/请求**；基线 ¥6.2/天 → 本窗口 **¥4.7/天** |
| 冷读 | 会话中途（`cr=0` 且未命中≥20k）：**78 次 / ¥12.30**（占 6.5%）；会话首个请求（预期内）：**0 次** |
| 子代理 | **33 个会话 / ¥12.91**，单任务均 **¥0.39**；`delegationDepth {0: 79, 1: 32, 2: 1}` |
| 交接 | `.handoff/` 下交接目录 **1 个**；主会话 **79 个**；最大上下文 **792275 tokens**；该交接之后的 24h 内主会话花费 **¥0.00** |
| 步骤重复 | 同一会话内同一条 shell 命令 ≥2 次：**293 处 / 43 个会话**（占 15.7% 的会话） |

### ⚠️ 读这份周复盘必须先知道的一件事

**`depth≥1 应为 0` 那条在本次运行里是假警报。** 脚本回看的是**历史日志**，它分不清
"护栏装上之前的老账"和"现在还在漏"：`standard-leash` 的递归护栏是今天
**2026-09-19 14:33** 才落地验证的（`3c3dd58`），本次窗口（`--days 40`）自然包含护栏生效之前的派发。
护栏本身在**真实调用**里已经验过（见 `docs/本地插件与治理融合.md`）。

⇒ **结论**：`weekly_review.py` 的"建议"节是**启发式**的，运行时间早于护栏落地时不能照抄。
判断"护栏现在有没有生效"要用**当下**的调用做实验，不能用历史日志统计。
（该脚本现已自带这条警告，见 `~/.dsh-analysis/weekly_review.py` §3 之后的引用块。）

同理，**§5 步骤重复 293 处**横跨整个窗口，绝大部分来自**未按交接规程**的早期会话
（指针没落盘 → 重复摸索）。它是"早期习惯"的度量，不是本套规程的 KPI。
