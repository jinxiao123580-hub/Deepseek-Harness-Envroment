# examples —— 一份真实交接件，以及它教了什么

[`2026-09-19-arm-handeye-calib/INDEX.md`](2026-09-19-arm-handeye-calib/INDEX.md) 来自一次真实交接
（项目细节、路径与数值**已脱敏改写**），保留的是"**交接文档会怎么错**"的形态。

它入选的原因不是写得漂亮，而是：**它的第一版被继任会话一轮自检抓出 9 个问题**，
而这 9 个问题几乎覆盖了交接文档的全部典型病症。

---

## 继任者抓出的 9 类问题（都可迁移到任何项目）

| # | 病症 | 表现 | 通用预防规则 |
|---|---|---|---|
| 1 | **路径/文件名错** | §6 验证命令写 `pose-plan-<日期>.json`，实际文件是 `plan-<日期>.json` | 验证命令必须**复制粘贴可跑**；写完自己跑一次 |
| 2 | **判据歧义** | "重投影 < 0.5 px" —— 已接受样本是 RMS 0.21 /**max 0.53**，按 max 读它自己就不合格 | 判据必须写明**统计量**（RMS / max / 中位）与**阈值来源** |
| 3 | **数字张冠李戴** | "新工具**现场 7/7 通过**" —— 实际是新工具**离线 6/6**，7/7 属于**另一个工具** | `[有效]` 必须附**证据**路径（输出/测试结果），**不能附脚本或源码路径** |
| 4 | **漏掉失败轴** | 只归因"几何是占位值"，但槽级记录显示还试过顺序/高度/roll 组合且全部 `unreachable` | "卡在哪"要写到**别人的结论会被它误导**的程度 |
| 5 | **采样可疑未标** | 40 个 segment 的 `worst` 只有 2 种形态 → 疑似只采样了起点 | 看似正常的数字也要标 `[存疑]`，并写清**为什么可疑** |
| 6 | **前提无落盘证据** | "某 API 已实测可用" —— 全仓库 grep **零命中**，只是交互式探针结论 | 技术前提要么有产物，要么标 `[存疑]` |
| 7 | **范围不匹配** | §1 目标写"第 1–6 节"，§2 只交代了第 2 节 | 目标里的每一项都要在"已完成/未决"里有落点 |
| 8 | **省略导致误读** | "改脚本时不要写进去" —— 缺宾语 | 省略的代价由继任者承担：宁可多一句 |
| 9 | **（正面）标注状态救了一次** | `[已否证]` 让"effort medium 生效"这条错误结论没有继续传播 | 三态标记不是形式主义 |

## 这份样例同时演示了正确的部分

- **头部字段齐全**：时间 / 本目录 / 上一个会话 / 继任档位与开场话术 / 检索预算
- **六字段齐全**：目标 / 已完成 / 未决 / 下一步 / 硬约束 / 验证方式（+ 指针）
- **零代码块零日志**：全部是指针（`→ 路径`），所以 60 行装下了 400+ 步工作的全部**接续要件**
- **指针化权威状态**：只写"`~/proj/HANDOVER.md` 顶部 `0A`"，不复述大文件
- **冻结执行**：交接后旧会话只打磨 INDEX，未继续推进任务
